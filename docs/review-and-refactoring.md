# 全库审查与重构评估

审查日期：2026-09-08。基线：`2390faf12c788c2239de178588c08477330224ca`，版本 `0.5.0`。

## 结论

需要局部重构，优先级高；没有充分证据支持整体重写、引入框架或迁移 TypeScript。

现有供应商注册表、凭据类别隔离、官方地址校验、存储格式及宿主槽位接入可以保留。主要风险来自跨模块行为契约不一致：供应商查询返回错误结果，而调度器只处理异常；配置、查询和插件生命周期没有统一的结果失效规则；流量事件与统计记账混杂，导致时间边界处理遗漏。

本次抽出两个可独立验证的模块：`lib/scheduler.js` 管理查询状态，`lib/usage.js` 管理样本替换。宿主入口负责实例装配，浏览器继续使用现有模块加载器和 React 槽位，无须新增构建流程。

## 各模块的必要性判断

| 模块 | 判断 |
| --- | --- |
| 宿主与调度 | 必须调整。生命周期与结果一致性影响所有供应商，本次优先完成。 |
| 用量记账 | 必须调整。统计错误会持久化，纯函数式调用入口便于验证跨时间边界。 |
| 客户端 | 修复交互和异步状态即可。大量篇幅为样式和词典，行数本身不足以证明需要全面拆分。 |
| 供应商查询 | 保留现有统一返回结构和元数据；修复分页完整性。按供应商分文件可后续进行，但当前收益低于运行时修复。 |
| 自动探测 | 保留普通 Key 与 Admin/Management 隔离、用户接管规则。探测结果增加版本门禁，避免旧探测覆盖新结果。 |
| 存储 | 保留版本 1 文件与原子替换策略。当前规模无需引入数据库。 |
| 测试与交付 | 增加统一 npm test 入口和依赖锁文件，补齐此前缺少的调度、生命周期和组件交互测试。 |

## 后续建议与限制

1. Anthropic 完整分页支持尚未实现。本次仅阻止不完整汇总；进一步实现前需要用真实响应或官方契约核实游标及重复桶规则。
2. 用量替换记录仅覆盖内存中当前轮次。跨插件重启的事件重放、旧轮次迟到、没有 turn/step 的重复样本，仍不能保证去重。需要宿主稳定事件 ID 后再设计持久化去重。
3. `sessionRouteSeen` 按会话 ID 保存且未主动淘汰，长期运行可能增长。应结合宿主会话删除/关闭事件实现回收，避免盲目设置上限破坏旧会话显示。
4. 存储仍使用同步文件写入，写入失败可能遗留临时文件。需要以真实文件规模和失败注入测试判断是否迁移到串行异步写入。
5. 兼容来源的手动 Base URL、无 Origin 客户端访问、反向代理认证均沿用本机信任模型；插件不提供独立远程鉴权。公开部署需要单独设计，不能把本次同源检查等同于身份认证。
6. 自动拷贝的密钥按现有契约视为已保存凭据，后续 DSH 密钥轮换不会自动覆盖。若需持续跟随，必须显式区分引用模式与手动模式。

## 验证边界

`npm test` 运行原有四组脚本与新增回归测试，供应商 HTTP 响应均为模拟数据。客户端测试使用真实 React 渲染器与模拟宿主槽位，覆盖点击行为和异步响应顺序。未连接真实 DSH 进程、浏览器页面或供应商账户，未核验上游 Windows 项目的私有文档，未验证在线 API 字段是否变化。

原有宿主测试在基线出现过同毫秒时间戳断言失败；其余三组原有脚本通过。最终 `npm test` 报告 14 个测试项全部通过，其中包含四组原有脚本及新增回归用例。全部 lib/*.js 语法检查及 `git diff --check` 均通过。审查完成时改动保留在本地工作区；后续根据发布要求将版本升级为 v1.0.0。
