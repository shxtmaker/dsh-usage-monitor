# dsh-token-quota 局部重构技术方案

日期：2026-09-12  
代码基线：main，9f63a1788557424dd8ace561a3346ee41a6099c2，v1.2.2

## 1. 目标与部署边界

本轮目标是修复异步状态一致性问题，降低不必要的请求、遍历和写入，并为后续维护建立明确边界。保留现有供应商注册表、凭据类别隔离、HTTP 查询保护、DSH 官方槽位、版本 1 小时桶格式和无构建客户端加载方式。

当前部署按两个独立执行环境处理：

| 部分 | 运行位置 | 本轮关注 |
| --- | --- | --- |
| 插件后端 | DSH 所在机器及其 Node.js 进程 | 扫描、配置提交、用量记账、状态生成、持久化 |
| WebUI | Windows 浏览器，也可能是其他浏览器客户端 | 请求生命周期、编辑草稿、告警显示、页面切换 |

DSH 后端实际操作系统和负载尚未核实。Windows 浏览器不意味着文件迁移及保存发生在 Windows。

未来 Windows 集成端分两类验收：仅封装 WebUI 时验证浏览器行为；本地启动 DSH 时额外验证 Windows 文件系统、插件卸载、进程退出和安装升级。当前不提前引入桌面专用接口或平台抽象层。

本轮不改变供应商覆盖，不引入数据库，不全面迁移 TypeScript，不全面拆分客户端，不增加密钥自动轮换策略。

## 3. 实施包 A：WebUI 请求与编辑状态

### A1. 用完成后调度替换固定间隔并发轮询

修改位置：lib/client.js 的 getState、post、useQuotaState。保持当前模块加载器和 factory，不新增浏览器 import 或打包步骤。

设计：

1. getState 接受 AbortSignal，检查 HTTP 状态和响应的 ok 字段。
2. 将 setInterval(load, 10000) 改为请求完成后 setTimeout。正常刷新等待 10 秒；失败按 10、20、40、60 秒退避，成功后复位。取消不计为失败。
3. 单个 hook 同一时刻最多一个后台 GET。对同一会话的重复 load 合并；会话切换取消旧请求并立即查询新会话。
4. 保留会话标识及请求代次校验。AbortController 用于释放请求，代次校验用于阻止不可取消或已完成请求回写；二者不能互相替代。
5. GET /state 初始超时设为 30 秒。超时保留最后有效状态并进入重试，不清空当前供应商。
6. 页面隐藏时停止后台定时器并取消后台 GET；恢复可见时立即刷新。显式用户操作不受后台暂停影响。清理 visibilitychange 监听及超时定时器。
7. 手动 refresh 开始时暂停 GET 轮询，取消旧 GET。合并重复点击的同一刷新操作；完成后发布结果并恢复后台轮询。
8. 不对所有 POST 使用 30 秒超时。refresh/test 涉及后端最长 120 秒查询，客户端初始等待上限设为 130 秒；settings/rescan 单独配置。连接断开不代表服务端操作被撤销。
9. 保留现有 20 项会话缓存上限。GET 超时与网络错误仅作为 WebUI 获取失败呈现，不篡改表示 DSH 事件通道的 traffic.channelAlive。

建议局部接口：

- getState(sessionId, { signal })
- post(path, body, sessionId, { signal })
- useQuotaState(sessionId) 返回 state、refresh、refreshing、loadError

Abort 超时由局部 helper 统一管理，使用 finally 释放定时器；测试环境补齐 AbortController、setTimeout 和可见性事件。

验收：

- 每次 GET 延迟 15 秒、连续三轮时，三个有效结果均能发布；最大后台 GET 并发为 1。
- GET 永不结束时，30 秒触发取消并按退避恢复，不积累悬挂请求。
- A/B 切页后 A 的迟到响应不得进入 B 的显示或覆盖 B 缓存。
- 隐藏超过 30 秒不发后台 GET，恢复只启动一次查询。
- 卸载后计时器和监听为零，不发布新状态。
- 手动刷新超过 10 秒仍能发布结果，不被后台请求作废。
- 保留窄侧栏、无调用会话、倒计时及弹层交互测试。

### A2. 给编辑器及异步操作增加身份

修改位置：lib/client.js 的 SettingsModal、reload、saveSupplier、saveGlobal、runTest、toggleEnabled。

设计：

1. editor 增加 editorId，每次打开供应商创建新标识；supplierId 不足以区分同一供应商的两次编辑。
2. 用 ref 保存当前 editorId、操作序号和 mounted 状态；关闭或切换编辑器立即使其失效。
3. 保存开始时捕获 editorId、supplierId 和表单快照。保存期间禁用当前表单编辑及重复保存，仍允许返回目录。
4. 请求成功后可以重新获取供应商目录，但只有 editorId 和操作序号仍匹配时，才能设置保存提示、关闭编辑器或写入错误。
5. reload 使用请求序号，旧目录响应不能覆盖新目录响应；刷新目录不重新初始化已存在的新草稿。
6. 连接测试绑定 editorId 和草稿修订号。修改字段后旧测试结果不能显示为当前草稿的结果。
7. 对启用开关使用按供应商的 pending 标记，防止重复点击发送相反状态的并发写入。
8. 返回目录或关闭弹层只取消本地 UI 回写资格。已经发出的设置保存仍可能成功，重新打开时以服务端为准，不自动重试结果不确定的保存。

验收：

- A 保存中返回目录、打开 B 并输入；A 成功或失败都不得清除 B 草稿或覆盖 B 提示。
- 保存 A 后重新打开 A，新编辑会话也不受旧回调影响。
- 编辑字段后旧连接测试返回，不显示为当前草稿测试结果。
- 保存失败时保留当前草稿；空秘密字段、组织 ID 及显式关闭语义保持。
- 浏览器测试通过延迟路由响应复现上述流程，不能只检查函数返回值。

### A3. 统一客户端告警判定

修改位置：lib/client.js 的 stateToken、EntryCard 及两个 EntryCard 调用点。

增加局部纯函数 classifyPct(pct, { warnPct, critPct })，默认值仍为 80/95。EntryCard 显式接收供应商阈值；详情和设置预览共用。stateToken 使用同一百分比判定。无值、未知值、请求错误继续独立处理，不把未知数字转换成正常的 0%。

设置预览继续表示已保存配置对应的查询结果，保存成功后刷新。若未来需要随未保存阈值实时变化，应另作明确功能变更。

验收覆盖：默认阈值；自定义 50/70 下的 49、50、60、70；null、undefined、NaN；详情、供应商状态和配置预览的一致性。

## 4. 实施包 B：扫描协调与发现状态

### B1. 抽出扫描协调器

新增 lib/scan-coordinator.js；lib/index.js 负责宿主接缝与装配；lib/detect.js 保留探测及纯补丁生成。

协调器维护 requestedRevision、completedRevision、runningPromise、disposed。扫描结果首先作为局部候选，提交前不得更新 runtime.harness、routeResolver 或可见发现结果。

入口约定：

| 触发原因 | 正在扫描时的行为 |
| --- | --- |
| 启动、常规周期 | 可复用进行中的扫描，不因定时到达而不断使有效结果过期 |
| 路由变化、凭据变化、相关外部配置变化 | 增加版本，当前旧候选失效，合并启动后续扫描 |
| 手动重新扫描 | 增加版本并等待至少该版本的新扫描；不能只等点击前的扫描 |
| 卸载 | 禁止新扫描及候选提交，释放等待者 |

扫描流程：

1. 捕获当前目标版本，读取 DSH 路由和凭据。
2. 每个关键 await 后检查 disposed 和版本。宿主凭据 API 不支持取消时允许底层调用结束，但不再提交旧结果。
3. 候选完成后进入插件内部设置写入队列，再次检查版本，并读取最新插件配置生成 autoFillPatch。
4. 发现用户已填写密钥或显式关闭后，不写相应字段。
5. 紧邻 ctx.settings.update 调用前再次校验版本；检查与调用之间不插入 await。
6. 成功后发布有效候选的发现状态，重新同步 scheduler 的有效配置，必要时取消旧查询。
7. 若等待期间产生新版本，继续后续扫描；若扫描失败，保留最后成功快照并明确记录本轮错误。
8. 手动请求按自己的目标版本等待，不等待无限持续变化。初始 30 秒未得到对应结果时返回失败及“稍后重试”，不能把旧扫描包装为成功；后台扫描可以继续。
9. 区分自动填入自身触发的 settings.watch 与外部变化。自身提交只需更新本地配置和调度器，不应形成无限重新扫描。外部无法区分时允许额外一轮幂等扫描，但测试必须证明会收敛。

可采用以下职责接口，具体名称可随代码规范调整：

- request({ reason, requireFresh })：合并或创建扫描，返回覆盖调用目标版本的 Promise。
- dispose()：阻止新的运行与发布。
- injected scan()、commit(candidate, isCurrent)：分别负责读取与受保护提交。

### B2. 设置写入一致性的保证边界

自动填入与插件 /settings 的写入使用同一串行队列，任务执行时读取最新配置。队列不增加持久化格式，仅协调本插件发起的写入。所有队列任务开始前检查生命周期。

本轮保证：自动填入在提交调用开始前仍对应最新已观测来源，并尊重当时已提交的用户设置。保留现有“首次复制、已有密钥不自动覆盖”的语义。

ctx.settings.update 是否提供版本比较或原子条件写入，当前仓库接缝不能证明。实施时核实实际 DSH 版本的 API：

- 有条件写入能力时，携带读取版本，冲突后重新读配置并生成补丁。
- 只有普通 update 时，使用上述插件内部串行化；不得声称可以原子阻止外部进程或宿主其他写者在提交执行期间修改配置。
- 来源变化若发生在 update 已开始之后，视为后续变化，按现有首次复制契约处理。不要通过事后覆盖用户密钥“补偿”。

这一区分必须在回归测试命名和运行时文档中说明。持续自动跟随凭据轮换需要单独定义凭据所有权，不纳入本轮。

### B3. 区分历史来源与当前发现

buildStatePayload 的 detectedNow 仅由最近成功扫描的发现集合计算，不能包含持久化 c.autoSource。

added = detectedNow || enabled || anySecretSet。

保留 autoSource 作为来源元数据，不自动删除历史配置。autoDetected 的布尔含义统一为当前发现；如原有 UI 需要历史来源，继续通过 autoSource 展示。扫描失败不等于供应商消失：保留上次成功发现结果，通过 detect.error 和最后成功时间标明未刷新。一次成功的空扫描才移除当前发现状态。

验收：

- 扫描等待凭据期间来源变更，旧候选不得进行首次密钥提交；新一轮填入新值。
- 同一窗口用户手动填写密钥或关闭供应商，自动填入不得覆盖。
- 扫描进行中删除路由并点击重扫，成功响应必须对应点击后的扫描。
- 无密钥、未启用、仅残留 autoSource：成功重扫后 added=false。
- 已有密钥或仍启用的供应商删除宿主路由后，依然可在目录中管理。
- 短时间连续事件只产生有界的后续扫描，不出现并发扫描或自身 watch 无限循环。
- 扫描失败、超时、卸载后无错误成功响应和迟到写入；已经进入宿主 update 的操作按上述保证边界验证。

新增 test/scan-coordinator.mjs，并在 test/detect.mjs、test/mock-dsh.mjs、test/runtime.mjs、test/route-consistency.mjs 补集成用例。

## 5. 实施包 C：低成本性能优化及兼容修复

### C1. 今日统计只读取当天 24 个键

在 lib/storage.js 增加纯读取 helper，或在现有统计职责内集中实现 sumDayTokens(hours, date)。使用本地 dayKeyOf(date) 加 00 至 23 构造键，最多查询 24 次；不要通过固定递减 UTC 毫秒推导本地小时。

buildStatePayload 开始时捕获一次 now，所有供应商共用该自然日边界。保持当前返回约定：总量大于 0 返回数值，否则为 null。不新增缓存，不新增午夜定时器，避免缓存失效和跨日状态维护。

该调整将每个供应商的今日统计从遍历 168/2160 个小时桶改为最多 24 次键查询；这是算法工作量变化，不承诺整个接口同比例提速。

测试覆盖：本地午夜、当天首尾小时、旧数据、空数据及两个不同时区进程。夏令时下继续遵循现有本地小时键格式，不在本轮改变持久化时区语义。

### C2. 相同用量样本不触发无效保存

createUsageRecorder 的返回值改为 changed 布尔值。相同已标识会话、轮次、步骤，且供应商、归属小时和 token 总量未变时返回 false；无效输入且未修改桶也返回 false。实际替换、扣减或增加返回 true。

index.js 只有 changed=true 才 markDirty 和 scheduleUsageSave。setRetention 引起的 dirty 仍独立生效。

保留首次报告小时归属、跨供应商扣减和同进程共享 recorder。未标识事件维持现有统计规则，不新增猜测去重；不承诺跨重启事件重放去重。

验收：

- 同一步骤相同最终样本重复 100 次，只在第一次产生桶变更。
- 同一步骤最终数量变化、供应商变化、跨午夜替换都保留现有正确总数。
- 高频相同样本的模拟宿主运行中，首次成功冲刷后不再重复写盘。
- 保留期变化仍触发修剪及保存。

### C3. 统一官方地址描述

lib/providers.js 现有 OFFICIAL_ENDPOINTS 作为唯一官方主机和基础路径策略，查询函数与探测校验共同引用。把声明移到不会触发初始化时序问题的位置。供应商解析函数保持独立。

保留 HTTPS、端口、用户信息、查询串、重定向拒绝规则；兼容来源的地址策略继续单独处理。通过测试比较每个官方供应商“探测可采纳地址”与“查询可使用基础地址”的集合，验证所有拒绝样本不触发网络调用。

此项收益主要是减少未来修改遗漏，性能收益不列入验收指标。

### C4. Windows 目录迁移修复

修改 lib/storage.js 的 migrateUsageDir：

- 检查旧目录存在且目标目录不存在，创建公共父目录后直接 rename，禁止预先创建目标目录。
- 目标目录已存在时不覆盖、不合并；目标 usage.json 不存在但旧文件存在时保留旧路径回退，并记录可诊断结果。
- EXDEV、EPERM、占用等失败继续读取旧路径，不删除旧数据。
- 覆盖成功迁移、新旧并存、目标空目录、权限失败及重复调用幂等。
- Windows/Linux CI 均需通过。当前部署不受影响时，该项仍可作为小型兼容修复独立合入，不能据此宣称当前服务器存在故障。

## 6. 持久化改造的启动条件

默认继续版本 1 文件、短写锁、跨进程增量合并、原子替换和失败退避。本轮先交付性能测量脚本，不直接改为异步存储。

### 6.1 可重复测量

扩展 scripts/benchmark-storage.mjs，并新增 scripts/benchmark-runtime.mjs。对当前实际 DSH 后端操作系统做前后对照：

- 供应商数：1、13；历史：7、90 天。
- WebUI 数：1、5、20，各按真实轮询节奏。
- 模拟事件速率：0、1、10、100 次/秒，区分相同样本重复和有效增量。
- HTTP 查询用固定模拟响应，避免压测真实计费账户。
- 每组预热 60 秒、采样 5 分钟、运行 3 轮。先测单客户端默认规模与 90 天压力规模；异常时再展开完整矩阵。
- 记录状态端点 p50/p95/p99、事件循环延迟、process.cpuUsage、RSS/heapUsed 趋势、保存次数/字节数/耗时、最大查询并发、生命周期结束后的剩余句柄。
- 内存判断比较预热后稳定区间和多轮挂载卸载后的残留，不能以单次 RSS 数字或尚未 GC 的对象判定泄漏。
- 测试报告记录 OS、Node、CPU、存储介质、样本数与配置。Windows 旧基准只作旁证。

### 6.2 决策门槛

以下是建议工程门槛，不是已测得的性能承诺：

- 默认单客户端、7 天规模无稳定回归；同机多轮中位数变化超过 10% 时先排查噪声和原因。
- 90 天状态生成中位耗时目标较改动前降低至少 50%；未达目标则检查剩余构建和序列化占比，不引入第二层缓存凑指标。
- 空闲且配置未变时保存次数为 0；相同样本重复在首轮持久化后不再导致写入。
- 存储同步段 p95 持续超过 20 ms，且能在真实宿主确认与状态响应或事件循环尖峰相关时，启动异步持久化专项。
- 用户可感知的停顿且经追踪证实来自持久化时，即使未达到数值门槛，也启动专项。

异步专项的最小设计：单个存储实例只有一个写入者，队列保留当前批次和后续合并增量；JSON 格式不变。flush 开始冻结待保存增量，保存期间新事件进入下一批；成功仅确认已持久化批次，失败保留原批次。不能在 await 后把 dirty 直接清零，否则会丢失等待期间的事件。

仅 fs I/O 慢时优先串行异步 I/O；合并、序列化及克隆也占主要时间时，再采用 Worker。Worker 不改变跨进程文件锁及合并规则。接入前核实 DSH 卸载是否等待异步 dispose；若宿主只提供同步清理，不把未等待的 Promise 当成退出冲刷成功。该能力未核实前不交付异步持久化。

- 本轮不升级 usage.json 格式，不迁移 settings 命名空间，旧版本仍可读取数据。

- 不把发布、推送或生产安装视为技术方案交付的一部分，实施完成后按实际发布要求执行。
